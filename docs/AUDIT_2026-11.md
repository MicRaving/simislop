This is the record of the full code audit run on 2026-11-14 and 2026-11-15. It is compiled from the per-slice
agent reports and the orchestrator's notes. Statements about runtime behaviour come from code reading and unit
tests unless the text says otherwise. Section 6 lists what was never run.

`Read` returns null. A test covers that (`TiffAndOtherUnregisteredFormatsAreRejected`). The licence question is in section 5.

## 2. Bugs fixed

One line per fix: what was wrong, the user-visible effect, the fix. "Not run" means the change has no automated test
through the production path (see section 6).

### 2.1 Neighbourhood 3D view, terrain, facades

- **World clock never advanced at 60 fps or more** (`SimitoneNeighbourhoodWorld.Tick`, N1a). Each call floored `deltaSeconds * TicksPerMinute` with no carry, and a 60 fps frame is 0.5 tick, so the floor was 0 every frame. Effect: the shared-world clock stood still. Fix: bank the remainder in `_tickRemainder`. 3 tests added.
- **Off-screen simulator speed was 0x to 2x** (`OffscreenSimulator.Tick`, N1a). `Math.Round` of 0.5 tick per frame. Effect: off-screen lots simulated at jittery speed, or froze above about 61 fps. Fix: the same remainder carry.
- **Only one facade was ever built in the surroundings** (`NeighbourhoodFacades.BuildStep`, N4b). `SimitoneSurroundings` never called `BeginFrame()`, so `FrameAllowance` stayed 0 after the first build. Effect: far neighbours stayed bare ground. Fix: `BuildStep` calls `BeginFrame()`. This is a probable cause of the "shared world substantially broken" report.
- **Facade GPU leaks and exception safety** (`NeighbourhoodFacadeBuilder`, N4b). Owned render targets were not disposed on null-return paths, a throw in the second or third surface lost the first surface's buffers, and `Scenes.Remove` and `world.Dispose` shared one `try`. Fixed in each place.
- **`NeighbourhoodFacade.PrimitiveCount` threw a NullReferenceException** for a house without a roof or floor, which is normal. Fix: null-conditional.
- **Facade draw left `SamplerStates[0]` changed.** It now restores it.
- **`Outstanding()` allocated a Dictionary and List every frame.** Added `NeighbourhoodFacadePlan.CountToBuild`.
- **A static facade mesh store could hand one facade to two caches** (N4b finding, fixed in S2). The first cache to drop it disposed the other's mesh, which then stopped drawing silently. Fix: `Take` removes the mesh from the store, so each facade has a single owner. The capacity went from 96 to 128, because 96 was below the maximum lot number of 98.
- **Draw failures and device loss were hard-coded to 0 and false** in `Neighbourhood3DView` (N4a, fixed in S2). `NeighbourhoodViewSetting` documents them as live fallback signals. Fix: a new pure `NeighbourhoodDrawHealth` counts consecutive failures, wraps `DrawFrame` in try/catch, and subscribes to `DeviceLost` and `DeviceResetting`. 7 tests.
- **A failed whole-map mesh build was silent** (`NeighbourhoodMeshGeometry.Build`, N4a). The failure is now logged and kept in `Failure`. `NeighbourhoodTerrainRenderer.BuildFailure` was always null and now returns it, and `IsBuilding` is false after a failure.
- **A failed upload left the rebuild flag set** (`_regenInProgress`). It is now cleared in `finally`.
- **Slice worker exceptions were swallowed.** They are logged and recorded in `FailedSlice`.
- **A superseded slice could upload over a newer one.** Added `_sliceSerial`.
- **A failed subdiv slice left `_subdivBusy` set forever.** Refined slices never drew again until reset. It is now cleared.
- **A per-frame `BoundingFrustum` allocation** in `Neighbourhood3DView.Draw` now reuses one field.
- **LOD changes allocated tens of MB of list capacity** (`NeighbourhoodCityMeshBuilder.Build`). Capacity is now divided by factor squared.
- **The surround shaders failing to load still produced a "successful" surround** (`SimitoneSurroundings` constructor, N2). It drew nothing while the log claimed success. `TryCreate` now refuses with the reason.
- **The surround terrain upload callback had no `catch`** (`SurroundTerrain.BeginMeshBuild`). A `VertexBuffer` throw escaped into the update loop. It now records `_failure`.
- **Repack lost per-lot session state** (`NeighbourhoodLifecycle.LayoutToWrite`, N3 finding, fixed in S2). `LotState` and `LastSimulated` are now carried by lot number, and `Entrance` is carried only if the lot's position and size are unchanged. With Persist on, hollow and active-lot state was previously lost whenever a house file changed. Test added.
- **Stale or contradictory layout tests and docs** (N3). `OverlapCounting_IsTheDiagnosticItAlwaysWas` asserted both ==0 and >0 for the same call. `PackedLayout()` now hand-places a centred block. Several docs claimed Part 8 placement or "nothing calls PackOnGrid" when it is the shipped packer.
- **`TS1LotContentSource.ReadLot`** reported `HasHouse=false` but kept `Rotation`, `BaseHeight` and grass variation from a half-read house. They are now reset.
- **`TS1LotContentSource.BackdropBitmap` leaked a FileStream.** The whole backdrop cluster was deleted as an orphan (section 3).

### 2.2 Shared and live neighbourhood world

- **The played lot floated or sank against the surround** (N2 defect 1). Its absolute `ARRY(0)` ground was drawn at `BaseAlt = 0` while the surround was measured to the map. Fix (S5, after S3 patched the wrong load path): the surround is lifted to the lot's ground; the lot itself is unchanged. See section 7. Not run.
- **Walkers stood at the blueprint's NW corner** (`TransitBlueprintPlan.LocalTileAt`, N1b). `LotTilePos` is in sixteenths of a tile and the method passed a raw tile count. Fix: `LotTilePos.FromBigTile`. Three tests that had encoded the bug were updated.
- **Failed transit-lot builds leaked a sub-world** (`TryBuild`). Both `return false` paths now dispose it, and the catch also removes it from `SubWorlds`.
- **Zero-length walk froze the lot** (S-2). With Walk on, travelling to the lot you stand in started a walk that `IsWalking` considered finished, and the lot stayed paused. Fix (S3): a same-lot request becomes a no-op with the speed restored, and `TryBeginTransitWalk` refuses `path.Length <= 0`. Not run. The pure state is pinned by `AZeroLengthWalkOwnsTheAvatarButIsNeverWalking...`.
- **Travel erased the "family comes too" signal** (`MirrorTransitToProvider`, D5/S-1). It wrote `LotTransitInfo = 0` after every completed switch, before the arrival script read it, so vacation and downtown arrivals always built one Sim. Fix (S3): write the field only when `travelling > 0`. Not run.
- **Cold-start world clock began on 1 June 1997** (D1/D2). The first handshake was skipped when the generated world was still pending, then B8 lighting lit the lot from the wrong clock. Fix (S3): `UpdateNeighbourhoodWorld` seeds an unseeded world clock from the lot clock before the first tick. Not run.
- **Every landing of a generated surround replaced `SurroundingsWorld`** (U2, `TS1GameScreen` ~587-596) before the stale-lot check, and `TryGetNeighbourhoodWorld` then dropped the live world and its clock. Fix (S3): replace only when null or the slot differs. The token check still gates the attach.
- **A `world.Tick` exception made the screen rebuild and throw every frame** (U2, `TS1GameScreen` ~820). The catch nulled the source, which cleared the Unavailable latch. The source is now kept.
- **Blank hollow neighbours withheld their facades** (S-7). Up to 12 neighbours were planned, 4 were built, and the facade of every planned lot was withheld, so 8 showed an empty plot. Fix (S3, partial): `SimitoneSurroundingsPlan.WithoutBlankNeighbours` and a `TryRestore` overload return the resolved plan, so blank neighbours show their facade. Loading the other neighbours on later frames is not done (section 4).
- **Template-load errors read the `vm` field a frame later** (`TS1GameScreen` ~3926). A lot switch in between could hit null or the wrong VM. The VM is now captured.
- **Every save leaked two GPU textures** (`SaveService.cs` ~169). Decimated thumbnails were not disposed after the PNGs were encoded. They are now disposed, except when `Decimate` returned its input.
- **`NeighbourHollowLoader` and `VM.HollowLoad` hardening** (S1). A missing definition GUID and duplicate object ids are skipped with a log line, instead of a null-object NRE or an `ObjectsById.Add` throw. A bad `FSOh` magic now throws `InvalidDataException` instead of leaving `Context == null`. 3 tests.

### 2.4 Utils, services, settings

- **`SimitoneIniFile.ReadLines` treated an unreadable ini as empty** (C1 finding, fixed in S4). A transient sharing violation during `SetAll` rewrote the file with only the new keys. It now logs, throws `IOException`, and `SetAll` aborts before `AtomicFileCommit`. `SetAll` also gained a static lock around read-merge-write, because two settings objects sharing `simitone.ini` could drop each other's keys. Test added.
- **`SimitoneNeighOBJExporter`** leaked `mtlIO` on exception (now `using var`) and never tore down the per-lot VM and world. Teardown is now in a `finally`: `SuppressBHAVChanges`, `CloseNet`, `Scenes.Remove`, `world.Dispose`.
- **`SimitoneLog.Format`** logged only the outer message and stack, which hid TypeInitializationException and AggregateException causes. It now appends the inner chain (depth cap 8). Test added.
- **`SimitoneGame` content-load failure** only wrote to the console, which a shipped game does not have. It now also logs. The audio-probe failure is logged too.
- **`BitmapDecoder`** is limited to BMP and PNG (section 1).
- **Corrupt `Neighborhood.iff` now fails loudly** instead of being replaced. See the FreeSO engine items below and section 5.

### 2.5 FreeSO engine

- **`TS1NeighborhoodProvider.CopyFolder` could destroy player data** (F1, fixed in S1). When `Neighborhood.iff` was missing but saves existed, it overwrote `Houses\House*.iff` with the template, and a failed copy deleted the whole folder. Now it never overwrites (`File.Copy(..., false)`), seeds only missing files, and rolls back only files and directories it created. 2 tests added and 1 updated. A side effect is that an existing but corrupt `Neighborhood.iff` is no longer replaced.
- **FAR3 decompressed size was read little-endian.** Restored to upstream big-endian in `FAR3Archive.GetEntry`, and `Decompresser.Compress` writes big-endian too. There is no FAR3 sample locally (0 hits across 12,382 files), so this was not checked against real data (section 5).
- **`VMMotiveChange.Tick` lost its MaxValue clamp** to an earlier "dead code" cleanup (E-37). It is reachable: the first `IsPastLimit` runs before the step, the second after. A change that crossed its limit overshot, and the "once" path disagreed. The clamp is restored and `VMModelWiringTests` updated.
- **`VMEntity.ClearStaleOccupied`** cleared `Occupied` per tile while its remarks promise a group-wide check, so opening a pie menu could clear the flag on the other half of a bed or sofa in use. Now no tile is cleared if any tile of the group is held.
- **`_2DStandaloneSprite`:** a partial vertex upload wrote at buffer offset 0, so a change to corners 2-3 overwrote corners 0-1 (corrupt headline quads). The "nothing changed" return also ran before the device check, so a sprite kept a dead buffer after a device reset. Both fixed.
- **`UIBufferPool`** had no synchronisation despite documenting resize-on-window-thread as safe, so a lock was added. `Replace` now retires buffers that are still checked out instead of disposing them (S4).
- **`UIRenderPlane.Dispose`** now always fulfils its promise, with null when the target is invalid, the device was invalidated, or the plane never bound (S4). Not headless-testable.
- **FreeSO City types:** F2 found that the "lifted" `CityGeometry` copy in `tso.world\City` was not an orphan, because `tso.client` (`Terrain`) uses `new CityGeometry()`. The original `tso.client\Rendering\City` files were restored from `HEAD` (content-identical, LF vs CRLF only). `tso.world\City` and `CityMapDataLoader` were deleted. The direct LotView ProjectReference in `FSO.Client.csproj` was removed.

## 4. Shared and live neighbourhood world: assessment

**Verdict: REPAIR, not rewrite.** The pure code is coherent and well tested. That covers flags, `WorldClock`, `LotStore`,
`TransitStore`, state, simulator maths, the planner, `TerrainFill`, `TerrainSeamSolver`, and over 360 surroundings
tests. The failures are in integration. Two parts are exceptions: **Walk** (B4, "continuous streets") should be **cut**,
and **Services** (B5) should be **trimmed**.

### 4.1 Root causes shared by several flags

- **R1: the world is not a session object.** `TS1GameScreen.NeighbourhoodWorld` is built lazily by `TryGetNeighbourhoodWorld` (`TS1GameScreen.cs` ~848-903) out of `SurroundingsWorld`, the layout and map the 3D surround fetched for the current lot. Every world capability therefore depends on the 3D setting being on, a lot number being known, and generation having finished. The world is absent otherwise, and nothing logs why. It was also dropped on every slot or source change, that is, on every travel between residential, downtown, vacation, studio and magic lots.
- **R2: nothing owns the lots.** The screen keeps its own `SavedLots` (`TS1GameScreen` ~3417) and never feeds `LotStore`. `SetActiveLot` and `SetActiveLotWith` have no callers, so lots the player has played are invisible to the world and to the off-screen simulator. Only hollow neighbour marshals published by the loader reach `LotStore`.
- **R3: two free-running clocks.** A lot's `VMClock` (pausable, game speed) and the world's `WorldClock` (wall-clock) both run while a lot is up and drift apart. The handshake only runs at load, stash and save.

### 4.2 Per flag

| Flag | Status before | Root causes | Fixed in phase 2 | Remains |
|---|---|---|---|---|

### 4.3 Decisions embedded in the verdict

- **Cut Walk.** Delete the second-VM half: `NeighbourhoodTransitLotVm` binder, `TryOpen` and `TryBuild`, the screen's `OpenTransitLotVm`, `ApplyPendingTransitArrival`, `PendingTransit*`, `TransitCamera`, and the "carried avatar" request field. That is about 2,600 lines that cannot be tested without a device and whose contract the engine cannot meet. Keep `NeighbourhoodTransitLot` (the route and progress planner, which is deterministic and tested) and either drop the flag or reduce Walk to a visual camera pan. A real rewrite would be a 2-3 week design change (one VM per world with the street in the active blueprint, or a position-only walk).
- **Trim Services.** Drop the `_world` plumbing and call it "leave-lot plus local architecture". Building the family-authority half is not worth it for a single-player game.

### 4.4 Remaining architectural repair plan

Sizes are the audit agents' estimates. Sizes: S is hours to a day, M is a few days, L is 1-2 weeks.

1. **World as a session object keyed by slot (M).** Build it from the neighbourhood lifecycle, not from the 3D surround's source. Compare slot rather than source instance. Log the reason when it is unavailable.
2. **Lot clock authoritative while a lot is up (S).** Pull the clock from the lot on first build and whenever its hour changes, and tick the world only when no lot is up. Alternatively, have B8 lighting read the lot clock.
3. **Route the stash through `LotStore` (M).** Move `SavedLots` behind `LotStore`, call `SetActiveLot` so the simulator excludes the played lot, and apply off-screen records back on restore (M).
4. **Wire Persist (S-M).** Call `ApplyWorldState(layout.WorldState)` right after the world is built, and `SaveWorldState` on lot exit and game save. Depends on items 1-3.
5. **Hollow-neighbour later-frame loading (M).** The loader built 4 of 12 per lot entry, and the rest are blank sub-worlds under facades. This needs a re-plan and a per-lot attempt latch redesign. Apply the existing `DefaultMaxMilliseconds` budget instead of leaving it at 0.
6. **Far-house facades (S-M).** `SimitoneSurroundings.cs:496` hands the facade cache only lots within the 40-tile cull, but the ground is the whole island, so bare plots show beyond it. Feed the full layout nearest-first within the per-frame budget (about 30 lines), and watch the cost, since each facade is a World+VM build on the game thread.
7. **Services trim (S).** Per 4.3. Also decide the fate of `LeaveLot`'s `avatar.Delete`.
8. **Walk removal, keeping the planner (M).** Per 4.3.
9. **`SimitoneGlobalLink` using the world (S-L).** Either drop `_world` (S) or implement family authority and occupancy (L, needs item 3).
10. **`NeighbourhoodWorldCamera` and `NeighbourhoodWorldLighting` are mostly unused (S).** Wire them into the 3D view fog, sky and sun, or cut them back to `OutsideColour` and `IsSunUp` and delete the tests that pin the rest.
11. **Surround cost (M, about 150 lines).** The full-map mesh (about 138k quads) is rebuilt on every lot entry with no cache, and the crop is a pass-through, so every frame submits all of it. Cache it per slot and add a frustum or chunk cut.
12. **Flag semantics (S).** The `Surroundings` flag gates only hollow sub-worlds. Rename it, or make it gate the drawn surround. Delete `SubWorldAttachEnabled` or make it the flag.

Rough total from N1a: 1.5-2 weeks for B1, B3, B6 and B7 to the handoff's acceptance criteria. That excludes the Walk rewrite and the surround cost work.

## 5. Open decisions for the owner

1. **ImageSharp.** It is pinned at 3.1.12 with six advisories suppressed. Decide whether to accept its licence terms or replace it. The decoder is already limited to BMP and PNG.
2. **FreeSO engine changes are uncommitted.** About 20,000 lines of Simitone's engine edits are not committed. The `simislop` gitlink (`7e76c19`) lacks them, so CI and fresh clones cannot build. A pushed fork branch is needed. CI will stay red until then.
3. **Credits panel.** `UICreditsPanel` (658 lines), `CreditsData` and `CreditsDataTests` have no caller. The Credits button was removed from the options strip (ADDON_PROGRESSION_PLAN Q3). Wire it into Options or delete all three.
4. **`UIPictureInPicture`.** About 1,200 lines, reachable only through the F9 debug key. Keep it as a debug feature, give it real callers (headline events), or delete it with `PictureInPictureTests` and `PipFeedFallbackTests`.
5. **Debug hotkeys in the shipped build.** F8 (the "Lot Thumbnail" dialog) leaks two textures per press, and F11 runs `VerifyAllCollision`. Gate both behind a debug flag, or delete them.
6. **BuildIde.** `BuildIde` defaults to true, so Simitone.Windows still references `FSO.IDE` and `FSO.Client`, and with them about 17 to 19 server projects (about 203 warnings). Only `FSO.Content.TSO`'s content survives into the release. Referencing `FSO.Content.TSO` directly would cut every build. That needs a measured diff of `bin\Release\net10.0-windows\Content`, and changes to `_SimitoneAssertNoIdeReferences` and `_SimitoneContentContract`. The CI budgets `WARNING_BUDGET(300)` and `NU1701_BUDGET(5)` were calibrated on the old closure (full build now 563-604 warnings) and have to be re-measured before the CI gates mean anything.
7. **`NeighbourhoodManager.CopyInto` race.** Between `RefuseToOverwrite` and the copy, another process creating the slot folder would have it deleted if the copy then fails, because `DiscardPartialCopy` removes the whole destination.
8. **`IniConfig.Save` (FreeSO).** It is not atomic (`FileMode.Create` truncates first, and a crash leaves a truncated `config.ini` that Load treats as defaults), it swallows every exception, so failed saves are silent, and it writes public read-only properties (`ActivePath`) into the file. The Options pages call it several times per interaction.
9. **Catalog icon textures.** `UICatalogItem` disposes evicted textures (and `ClearIconCache` all of them) while built rows still hold them in `Icon`, so a disposed texture in a still-built row throws on draw. Needs a draw-time fetch or a row rebuild on eviction. The 256 cap makes it rare.
10. **`EODLayoutWriter`.** Nothing can run this documented regeneration tool (no test, no CLI). Add a skipped test or tool entry point, or accept that.
11. **`CheatRunner` "five traits".** `TraitSlots` and `CheatConsoleTests` say five personality traits but six slots are listed (including Generous). Decide whether Generous belongs.
12. **`EODHost.Place()`** sizes from `GlobalSettings.Default.GraphicsWidth/Height` rather than the live screen. Verify under HiDPI and windowed.
13. **Corrupt `Neighborhood.iff`.** It now fails loudly instead of being silently replaced by the template. That is the intended trade for never deleting saves, but it means a damaged file needs a manual fix.
14. **FAR3 endianness.** The decompressed-size field was restored to big-endian from the RefPack spec and upstream FreeSO. No FAR3 sample exists locally to confirm it. If it is wrong, every compressed FAR3 entry fails with "declared size" errors.
15. **Smaller items.**
    - `SPR2.Read` now throws on a non-monotonic offset table, where it used to load a guessed size.
    - `VMExpression.TryGetFlagBit` caps flag bits at 1-16, where the old code allowed 32 on big variables.
    - `VMRoutingFrame.PortalTurnsActual` is not serialised and is approximated on load.
    - `VMArchitecture.BuildBuyEnabled`'s getter mutates, which is safe on one thread.
    - `VMEntity.GetPieMenu*` now mutates state and logs, which is fine for single-player.
    - `VMNetAdjHollowSyncCmd.Deserialize` still has an unbounded array read.
    - `TimedReferenceController.Clear()` called twice in both `CleanupLastWorld`s, `LoadingGameScreen` hanging if content loading throws, and `UIIconCache.ClearAvatarHeadCache` never being called.
    - `UIHouseFamilyList.PopulateList` builds a whole World+VM per panel build and never disposes the VM.
    - `NeighbourhoodFoliage.ChunkBoundsFor` culls with boxes up to 41% too tight at screen edges, and fixing it changes numbers pinned in `NeighbourhoodCitySkyTests`.
    - `PrepareFacadeLighting` swallows all exceptions with no log.
    - Linux and macOS locators are unreachable in a `net10.0-windows` WinExe.
    - `Simitone.MeshCleanup` is in no build graph and can rot.
    - Release `Version` 1.0.0 makes the update checker treat every 0.x tag as older.
    - `.gitmodules` points at `github.com/alexjyong/FreeSO`.

## 7. S5 — played-lot altitude anchoring

S3 called `Blueprint.AnchorBaseAltitude()` from FreeSO `VMTS1Activator.LoadFromIff` to fix the played lot floating or sinking relative to the surround (N2 defect 1). That was the wrong path: `VMTS1Activator` only builds the throwaway neighbour, facade and OBJ-export worlds, while the played lot loads through `VMBlueprintRestoreCmd` → `VMTS1ActivatorNew` → `VM.Load`.

S5 (report `reports\S5.md`) resolved it the other way round:

- **Datum.** The surround is measured down to the active lot's own map ground (the mean of its four centre elevation bytes); neighbour sub-worlds hang from the same plane.
- **Why the lot's `BaseAlt` is not changed.** Walls, roofs, floors, avatar positions and multitile groups bake the altitude (already net of `BaseAlt`) into their geometry when built, so changing `BaseAlt` after a late surround attach would leave them at the old datum. The played lot keeps `BaseAlt = 0`; its rendering is byte-identical to before whether the surround is on or off.
- **S3 reverted.** The `AnchorBaseAltitude()` call in `VMTS1Activator` is gone (facades subtract their own ground sample and hollow neighbours overwrite `BaseAlt` in a temp VM, so the revert changes nothing there); comments in `Blueprint.cs` and four other files corrected.
- **New anchoring.** The surround's world matrix is lifted by `(median(Altitude) − BaseAlt) × 0.01875 × 3` via `FollowLotGround`, called on attach and per frame, recomputing only when the `Altitude` array object changes (lot load, save/reload, template reset). With the surround detached nothing runs; a lift of 0 returns the old matrix unchanged. Sub-worlds get the same lift through a `BaseAltitudeFor(a, n, lotGround)` overload.
- **Test.** `ThePlayedLotKeepsBaseAltZeroAndTheSurroundIsLiftedToItsGround` (pure). The existing `AnchorBaseAltitude` arithmetic tests are kept.
- **Not verified in game.** The visual join at the property line; whether `Blueprint.Altitude` is populated at attach time (if not, the lift is 0 until a later frame); sub-worlds read the lot's ground once at restore time; `NeighbourhoodTransitLotVm` (Walk, slated for removal) still assumes a zero-ground lot.

## 8. Final state (2026-11-15)

- **Build:** `dotnet build Client/Simitone/Simitone.sln -c Release --no-incremental` - 0 errors. The Simitone projects (client, Windows, tests, tools) compile with **zero warnings**; the full closure has 675 unique warning lines, all in the FreeSO tree (336 of them NU1701 from 19 packages). CI budgets were re-measured to match: `WARNING_BUDGET: 700`, `NU1701_BUDGET: 19`.
- **Tests:** 8133 passed, 0 failed, in three consecutive full runs. Baseline was 8220; the difference is orphan tests deleted with the code they covered (section 1), the eight string-table cases for ids 250-257, net of about 20 tests added.
- **Also fixed during finalisation:** 45 xUnit analyzer warnings in the tests (H4), including `UIBufferPoolTests` asserting `NotSame` on a value type (an assertion that could never fail); 22 tracked FreeSO tool build artifacts that the 2026-11-14 disk cleanup had sent to the Recycle Bin were restored from FreeSO `HEAD`; `.claude/` (local session state) is now git-ignored.
- **Reproducibility caveat:** the FreeSO changes this audit made (and the ~20k lines Simitone already depended on) live only in the local FreeSO working tree. `simislop` pins FreeSO at `7e76c19`, so CI and fresh clones build stock FreeSO and will fail until those changes are committed to a FreeSO fork branch and the gitlink is moved (section 5).
